1. Executive Summary
--------------------

Authenticated EODHD and Twelve Data access does not exist in this environment. Cross-provider OHLCV comparison is not performed.

Mubasher was TESTED on 16 EGX names: quote JSON + full historical CSV.

- Daily history is deep (about 5–25 years depending on listing).
- CSV OHL + volume on the last session usually match the live priceBar.
- Live last (bar.value) often does not equal CSV close.
- change / changePercentage do not match (last − previousClose) / previousClose for most names (12/16 percent fields fail a 0.05-point tolerance).
- Mubasher CSVs are not split-back-adjusted at the documented COMI 1.1 split on 2025-12-17 (TESTED + DOCUMENTATION VERIFIED). Older years contain spike-then-revert rows that look like data errors, not clean adjustments.
- Recommendation: Mubasher daily CSV can be the temporary historical foundation only with conditions. Quote change fields must not be treated as authoritative. Phase 2 adapters can start; Phase 4 backtests must not treat the series as total-return adjusted.

7. Mubasher Change Field Analysis
---------------------------------

Independent calc (TESTED):

change = live.value − bar.close  
changePercentage = change / bar.close × 100

Tolerance: |Δchange| ≤ 0.02 or |Δ%| ≤ 0.05 for the percent field.

| | Match | Fail |
|---|---:|---:|
| change vs calc | 6/16 | 10/16 |
| changePercentage vs calc | 4/16 | 12/16 |

Both fields match on: EAST, MFPC, JUFO, CIRA only.

Examples (TESTED):

- COMI: bar +1 / +0.74% vs calc +2.03 / +1.49%
- ADIB: bar −0.44 / −0.82% vs calc +0.14 / +0.26% (wrong sign)
- TMGH: bar +0.70 / +0.72% vs calc −0.46 / −0.47% (wrong sign)

bar.change also does not match CSV last.close − prev.close on 0/16 names.

Recommendation (do not implement here): These fields should not be treated as authoritative. Recompute from chosen close definition after that definition is chosen.

App today: if bar fields exist, they are passed through (fetchMubasherQuote), so production change / changePercent inherit this error.

9. Corporate Action / Adjustment Analysis — BLOCKER
---------------------------------------------------

Do not treat this as a footnote. Unadjusted history breaks:

- multi-year % returns and momentum (momentum5, scores)
- moving averages / EMA stack / EMA200 (levels jump at split without restating history)
- RSI/MACD (close-to-close changes include the split gap)
- ATR and stop distances
- any backtest that compounds CSV closes

Mubasher CSV has no adjClose, no split ratio, no dividend field. TESTED.

Mubasher adjustment status = PARTIALLY VERIFIED

Meaning:

- We verified one split event and proved the series is unadjusted there.
- We did not verify a full CA calendar (all splits, bonuses, dividends) for the 16 names.
- We must not upgrade that to “VERIFIED adjusted” or “safe for indicators.”

Evidence: CSV is not split-back-adjusted (COMI 1.1)

DOCUMENTATION VERIFIED: COMI forward split 1.1, effective 17 Dec 2025 (stockanalysis.com / Investing.com).

TESTED CSV:

| Date | Open | Close |
|---|---:|---:|
| 2025-12-16 | 118.1 | 117.5 |
| 2025-12-17 | 106.82 | 103.8 |

117.5 / 1.1 = 106.818… equals 17 Dec open. Closes before the split stay on the old scale. A split-adjusted vendor would restate 16 Dec downward. Mubasher did not.

Implication for this repo: analyzeQuote() uses quote.candles[].c as a single continuous series. Across 16 Dec → 17 Dec that series contains a ~11.7% gap that is corporate action, not trading. Indicators computed on 3mo/max windows that straddle this date are not comparable to a split-adjusted series.

FWRY / TMGH / ORAS: no ≥25% jumps in the scan — does not prove dividends are adjusted (many EGX dividends are smaller than 25%).

SWDY / COMI 2008–2010 +300% then revert next day: not the 2025 1.1 split. Cause not verified (print error vs undocumented CA). Still unsafe to feed into returns.

Dividends: UNKNOWN (absent from CSV).

Required before trusting historical indicators / Phase 4: an external corporate-action table (or a vendor that supplies adj_close) applied in the normalized data layer. Mubasher will not provide this flag. This item is not deferred as optional polish.

18. Conditions for Using Mubasher
---------------------------------

Allowed as temporary primary if:

1. Historical bars use CSV OHLCV, not overwritten last, or last is stored as a separate field.  
2. change / changePercentage are recomputed after choosing last vs close.  
3. Split/dividend corporate-action table is applied outside Mubasher (or series labeled unadjusted).  
4. Invalid OHLC and spike-revert days are quarantined.  
5. Universe is active listings only until a symbol master exists.  
6. A validation vendor (EODHD or Twelve Data with keys, or licensed EGX files) is added before trusting Phase 4 results.
